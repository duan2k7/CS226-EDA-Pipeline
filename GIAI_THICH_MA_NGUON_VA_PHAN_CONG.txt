PHẦN 1. BẢN CHẤT MÃ NGUỒN NÀY DÙNG ĐỂ LÀM GÌ?
--------------------------------------------------------------------------------
1. Bối cảnh:
   Trong ngành thiết kế vi mạch (IC Design / FPGA), các kỹ sư làm việc hoàn toàn
   trên Linux và viết code mô tả phần cứng bằng ngôn ngữ Verilog HDL.
   Sau khi viết code một con chip (ví dụ: bộ đếm 8-bit counter_8bit), người kỹ
   sư bắt buộc phải trải qua 3 khâu kiểm tra:
     - Khâu 1 (Mô phỏng - Simulation): Chạy giả lập trên phần mềm xem mạch tính
       toán đúng hay sai, vẽ sóng tín hiệu điện.
     - Khâu 2 (Tổng hợp - Synthesis): Dịch code Verilog thành các linh kiện bán
       dẫn thật (cổng AND, OR, Flip-Flop, MUX...).
     - Khâu 3 (Đọc Log & Báo cáo): Đọc file nhật ký dài hàng nghìn dòng xem có
       bị lỗi cú pháp không, mạch tiêu tốn bao nhiêu cổng logic.

2. Nỗi khổ nếu làm thủ công:
   Nếu gõ lệnh bằng tay, mỗi lần sửa một dòng code, kỹ sư phải mở Terminal và gõ
   hàng chục lệnh dài dòng lặp đi lặp lại. Một ngày chạy 30-50 lần rất dễ gõ nhầm
   và cực kỳ mất thời gian.

3. Giải pháp của bộ mã nguồn này:
   Nhóm mình đã viết một hệ sinh thái các file Bash Shell Script (.sh) để biến
   toàn bộ quy trình thủ công phức tạp thành MỘT CÂU LỆNH DUY NHẤT:
       ./eda_pipeline.sh --all
   Chỉ mất đúng 0.2 giây (173 ms), máy tính sẽ tự động chạy toàn bộ dây chuyền từ
   kiểm tra file -> mô phỏng -> tổng hợp -> bóc tách log -> in ra báo cáo tóm tắt
   hoàn chỉnh (cả dạng Text xem trên Terminal và dạng Web HTML trực quan).

PHẦN 2. MÃ NGUỒN NÀY HOẠT ĐỘNG NHƯ THẾ NÀO? (LUỒNG DỮ LIỆU TỪ A ĐẾN Z)
--------------------------------------------------------------------------------
Toàn bộ dự án được tổ chức theo dây chuyền khép kín (EDA Pipeline):

[Bước 1] Khởi tạo môi trường & phân quyền (File: scripts/01_setup_project.sh)
   - Đọc file cấu hình config/eda.conf để lấy tên dự án, tên module vi mạch.
   - Tự động dùng lệnh 'mkdir -p' tạo chuẩn 6 thư mục chức năng:
       + src/     : Chứa code Verilog của mạch (counter_8bit.v)
       + tb/      : Chứa testbench kiểm thử (counter_8bit_tb.v)
       + config/  : Chứa file cấu hình tham số eda.conf
       + scripts/ : Chứa các script thực thi con
       + logs/    : Chứa lịch sử file nhật ký chạy
       + reports/ : Chứa báo cáo tóm tắt (Text và HTML)
       + results/ : Chứa file sóng .vcd và file Netlist mạch sau tổng hợp
   - Dùng lệnh 'chmod 755' tự động cấp quyền thực thi cho tất cả script.

[Bước 2] Chạy mô phỏng mạch số (File: scripts/02_run_sim.sh)
   - Kiểm tra xem file src/counter_8bit.v và tb/counter_8bit_tb.v có tồn tại không.
   - Gọi bộ công cụ Icarus Verilog để biên dịch:
         iverilog -o results/sim.out src/counter_8bit.v tb/counter_8bit_tb.v
   - Chạy mô phỏng bằng công cụ vvp:
         vvp results/sim.out
   - Xuất dữ liệu biểu đồ sóng điện tử ra file results/waves.vcd.
   - Ghi lại toàn bộ tiến trình vào file logs/sim_TIMESTAMP.log.

[Bước 3] Tổng hợp mạch logic (File: scripts/03_run_synth.sh)
   - Tự động tạo script tổng hợp Yosys (results/synth.ys).
   - Gọi bộ công cụ Yosys Open SYnthesis Suite:
         yosys -s results/synth.ys
   - Chuyển đổi mã Verilog thành Netlist cổng logic thực tế: results/counter_synth.v.
   - Đếm tài nguyên vi mạch (Cell Count): thống kê mạch tốn bao nhiêu cổng AND,
     XOR, MUX, D-FlipFlop.
   - Lưu toàn bộ kết quả vào logs/synth_TIMESTAMP.log và reports/synth_stat_TIMESTAMP.txt.

[Bước 4] Phân tích Log & Tạo báo cáo tự động (File: scripts/04_parse_log.sh)
   - Sử dụng các lệnh UNIX kinh điển (grep, awk, sed, wc) để tự động quét log:
       + grep -i -E "(error|fail)" : Tìm và đếm số lỗi cú pháp, lỗi logic.
       + grep -i -E "(warning|warn)": Tìm và đếm số lượng cảnh báo.
       + awk: Bóc tách chính xác khối thống kê 63 cổng logic từ log của Yosys.
   - Xuất ra 2 bản báo cáo đồng thời:
       + Bản Text: reports/summary_report_TIMESTAMP.txt (xem ngay trên Terminal).
       + Bản Web: reports/summary_report_TIMESTAMP.html (mở bằng trình duyệt).

[Bước 5] Điều phối trung tâm Master Pipeline (File: eda_pipeline.sh)
   - Là "bộ não" chỉ huy, kết nối Bước 1 -> Bước 2 -> Bước 3 -> Bước 4.
   - Hỗ trợ cả 2 chế độ:
       + Chế độ tham số dòng lệnh CLI: --all, --setup, --sim, --synth, --report, --clean.
       + Chế độ Menu số tương tác: gõ ./eda_pipeline.sh để chọn từng bước bằng menu.

    + Dùng Shell Script: Chỉ mất 2.11 giây, 0 lỗi sai.

        1. Kiểm tra sự tồn tại của file code và testbench.
        2. Biên dịch mã nguồn Verilog thành file binary results/sim.out.
        3. Chạy mô phỏng bằng 'vvp' và xuất file sóng results/waves.vcd.

         và xem biểu đồ sóng trực quan (lệnh: gtkwave results/waves.vcd).

PHẦN 4. HƯỚNG DẪN THỰC HÀNH CHẠY THỬ TRÊN MÁY TÍNH
--------------------------------------------------------------------------------
Để tự chạy thử trên máy Linux hoặc máy ảo Ubuntu, mọi người chỉ cần gõ 3 bước:

Bước 1: Mở Terminal và di chuyển vào thư mục dự án
    cd 2026S_CS226_Nhom04_DT18

Bước 2: Cài đặt các công cụ bổ trợ (chỉ chạy 1 lần)
    sudo apt update && sudo apt install -y iverilog yosys gtkwave

Bước 3: Chạy thử các chế độ
    - Chạy tự động trọn gói từ A đến Z:
        ./eda_pipeline.sh --all

    - Chạy ở chế độ Menu số trực quan:
        ./eda_pipeline.sh

    - Xem biểu đồ sóng tín hiệu dạng số:
        gtkwave results/waves.vcd

    - Xem báo cáo giao diện Web HTML:
        xdg-open reports/summary_report_*.html

    - Dọn dẹp các file rác và log cũ:
        ./eda_pipeline.sh --clean
